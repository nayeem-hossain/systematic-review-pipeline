# Example run: ML-IDS search

This directory holds a small, curated sample of real output from one end-to-end
run of the pipeline, so you can see the CSV and figure shapes without having to
run the scripts yourself first. `output/` and `pdfs/` hold the full,
un-curated run this sample is drawn from.

The worked example domain is machine-learning / AI-based intrusion detection
systems (ML-IDS) -- see the README's "Worked example" section for the full
Boolean query strings this run's search term is drawn from.

## Exact commands run

```bash
pip install -r requirements.txt

# 1. Search four APIs for a small ML-IDS query, capped at 30 records/source
python search.py \
    --query "intrusion detection AND machine learning" \
    --year-from 2020 --year-to 2026 \
    --mailto <your real email> \
    --max-per-source 30 \
    --out output/candidates.csv
# -> 90 records: 30 OpenAlex + 30 Crossref + 30 arXiv.
#    Semantic Scholar's unauthenticated pool returned HTTP 429 (shared rate
#    limit exhausted) at run time; search.py logs this to stderr and continues
#    with the other three sources rather than aborting the run. Re-run later,
#    or pass --s2-api-key, to include Semantic Scholar.

# 2. De-duplicate by DOI, then fuzzy title match
python dedup.py --in output/candidates.csv --out output/candidates_dedup.csv \
    --title-threshold 92
# -> 90 in, 0 flagged duplicate, 90 unique. This particular 90-record sample
#    happened to have no cross-source overlap (each API's top results for this
#    query didn't collide) -- the duplicate_of / dedup_method columns are still
#    present in the output and are exercised by the dedup logic on any corpus
#    where the same paper is indexed by more than one source.

# 3. Build the screening spreadsheet
python screen.py --in output/candidates_dedup.csv --out output/screening.csv
# -> 90 rows, decisions blank for a human reviewer to fill in.

# 4. Resolve and download open-access PDFs
python download.py --in output/candidates_dedup.csv --mailto <your real email> \
    --outdir pdfs --max-downloads 6
# -> 6/12 downloaded (6 arXiv preprints via direct link, plus -- after retrying
#    with a genuinely deliverable email address, see the gotcha below -- 6 more
#    IEEE Access / Springer gold-OA papers via Unpaywall).

# 5. Verify 10 citations against Crossref (fabricated-citation guard)
python verify_citations.py --csv output/candidates_dedup.csv \
    --doi-col doi --title-col title --limit 10 \
    --out output/citation_verification.csv
# -> 10/10 passed: every claimed title matches what its DOI actually resolves
#    to on Crossref.
```

## The extraction + figures demo (screening_decided_sample.csv onward)

`screening_sample.csv` above (and the real `output/screening.csv`) ship with
every decision column blank, by design -- `screen.py` never fills them in,
a human does. To demonstrate what `extract.py` and `figures.py` produce once
that human step has happened, this directory also carries a second, decided
version of the same 21-record sample plus a filled-in extraction/quality
sheet, built by hand from the same real ML-IDS records above (not a new
search -- same 21 ids, same titles/DOIs, just carried through the rest of the
pipeline):

```bash
# 6. Screen all 21 records (title/abstract, then full-text) -- illustrative
#    decisions on the same 21 real records as screening_sample.csv, kept as
#    examples/screening_decided_sample.csv rather than regenerated by
#    screen.py, since the decisions themselves are the human step.
#    -> 18/21 included at title/abstract, 3 excluded (2 off-theme, 1 off-topic);
#       15/18 included at full text, 3 further excluded (1 near-duplicate
#       contribution, 2 out of scope for the RQs) -- see the ta_reason/
#       ft_reason columns for the specific call made on each.

# 7. Build the extraction template from the decided screening sheet
python extract.py --in examples/screening_decided_sample.csv \
    --candidates examples/candidates_dedup_sample.csv \
    --out /tmp/extraction_template.csv
# -> 15 rows marked include in 'ft_decision'; template columns
#    (thematic_class, study_type, contribution, key_findings, rq_mapping,
#    limitations, venue_tier, R, A, T, C, quality_tier) blank for a human.
#    examples/quality_scored_sample.csv is what that template looks like once
#    a reviewer has filled it in for all 15 included studies.

# 8. Render the PRISMA flow diagram + quality-/venue-tier charts
python figures.py \
    --screening examples/screening_decided_sample.csv \
    --dedup examples/candidates_dedup_sample.csv \
    --candidates examples/candidates_sample.csv \
    --quality examples/quality_scored_sample.csv \
    --outdir examples/figures
# -> PRISMA counts printed to stdout: identified 21, duplicates removed 0,
#    screened 21, excluded at title/abstract 3, assessed at full text 18,
#    excluded at full text 3, included 15 -- all derived straight from the
#    two CSVs above, matching the ta_decision/ft_decision columns exactly.
#    quality-tier counts: A=4, B=7, C=4. venue-tier counts: T1=0, T2=5, T3=10
#    (all 5 arXiv preprints land in T2; everything else -- IEEE Access,
#    Procedia, a thesis, book chapters -- lands in T3 by the README's Stage 5
#    definitions; this sample simply never turned up a flagship T1 venue).
```

## A real gotcha hit during this run

Unpaywall's API (`api.unpaywall.org`) rejects requests whose `email` parameter
looks like a placeholder -- specifically, any `@example.com`/`@example.org`
address gets an HTTP 422 with `"Please use your own email address in API
calls."` OpenAlex and Crossref's polite pools accept `@example.com` addresses
without complaint, so this only surfaces once you run `download.py`. Use a
real, deliverable mailbox for `--mailto`/`MAILTO` if you need `download.py`'s
Unpaywall path to work -- not a `user@example.com`-style placeholder.

Note one intentionally-left-in artifact in `candidates_sample.csv`: record 64
("A Benchmark Study of Machine Learning Models for Online Fake News
Detection") is topically off-target -- it surfaced from arXiv's all-fields
search, not a title-field Boolean query, and is exactly the kind of
false-positive a human reviewer excludes at the title/abstract screening
stage. Real pipeline output is left un-cleaned here deliberately, as a
reminder that automated discovery always needs a human screening pass before
anything gets called an "included" study. (This is also exactly why record 64
is `ta_decision=exclude` rather than included in `screening_decided_sample.csv`.)
